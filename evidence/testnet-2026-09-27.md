## Failure paths exercised (agreement id 1)

Each of these is a genuine RPC simulation performed against the live
deployed contract on Testnet, using the real current on-chain state.
None of these reached ledger inclusion, because Soroban simulation
rejects the call before a transaction is ever submitted when the
contract would return an error; this is expected and correct CLI
behavior, and it is real evidence that the deployed contract enforces
its own rules, not a mocked local test. No transaction hash exists for
these because none was ever submitted to a ledger.

| Scenario | Contract error returned | Classification |
|---|---|---|
| Attester calls settle, naming itself as sponsor | `Error(Contract, #2)` = Unauthorized | VERIFIED LIVE (simulation rejected, not submitted) |
| Sponsor calls settle before care_deadline has passed | `Error(Contract, #11)` = CareDeadlineNotPassed | VERIFIED LIVE (simulation rejected, not submitted) |
| Sponsor calls fund again on an already-Funded agreement | `Error(Contract, #4)` = InvalidState | VERIFIED LIVE (simulation rejected, not submitted) |
| Provider calls cancel while agreement is CareConfirmed, not Requested | `Error(Contract, #4)` = InvalidState | VERIFIED LIVE (simulation rejected, not submitted) |
| Provider calls open_dispute before the dispute window opens | `Error(Contract, #12)` = DisputeWindowActive | VERIFIED LIVE (simulation rejected, not submitted) |

Error codes map to `contracts/care-agreement/src/lib.rs`'s `AgreementError`
enum exactly as defined in source; they were not assumed.
